# Validated opening checkpoints

The field viewer's **Jump to checkpoint…** picker offers five stages for each
starter: Route 29, Before rival, After rival, Before tutorial and After tutorial. **Back** returns to the exact prior
in-memory session, including a conversation or battle that was suspended. The
picker loads a prepared run; it does not teleport your current party or alter
that session's flags. The old session remains owned until replaced or the app
closes. Back retains the most recent prior session, not an unlimited history.

The fifteen ignored files in `build/checkpoints` are generated by running the
connected original opening route for Chikorita, Cyndaquil and Totodile. No quest
flags or gift items are injected to manufacture checkpoints. The healing fixture
in the route test is indoors and is repaired by the original Mr. Pokémon heal
before later checkpoints. Version 3 snapshots contain all 42 original normal
records plus native RNG/temporary continuation state, the map, position,
facing and Running Shoes state. Restoring constructs the field from that story,
then uses the existing original resume/actor/follower services.

Generation on a clean build:

```sh
cmake --build build --target heartgold_checkpoints -j8
./build/heartgold_field_viewer
```

The full test suite also regenerates them. These are native development
checkpoints, distinct from the original-manager Save/Continue controls. They may be rejected after a checkpoint schema change. Do not commit
the binary files or generated screenshots.

Validation rejects unsupported stages/maps, incompatible versions/sizes, damaged
checksums, invalid party records, missing starter/Pokégear/Elm prerequisites and
missing later-opening Pokédex/Egg/Apricorn Box/Oak/call prerequisites. The stored
starter must match the original starter variable, have usable HP, and carry the
correct rival visibility for the stage. Writes require an idle field, never a
half-completed battle or cutscene. File replacement is staged through a temporary
file and rename. A failed load keeps the current session.

`connected_checkpoint_resume` executes the next meaningful gameplay from loaded
states: Route 29 through Cherrygrove's tour; all three rival fights; no rival
retrigger after departure; and the rival's actual allowed-loss healing branch.
It also rejects a damaged snapshot. The native UI smoke checks the picker,
battle display/cutscene completion and Back's exact owner/revision restoration.
ASan covers the full opening and loaded checkpoint scenarios without memory-error
reports; original-code signed-shift UBSan findings remain.

The guarantees cover these tested opening checkpoints. They do not make later
unported scripts or arbitrary map-browser jumps playable. The original nickname
application still requires choosing No; the catching tutorial and later opening
work remain unfinished. General blackout recovery and the original Save menu are
not implemented.

Historical version 2 added the original misc record and rival name. Both versions
1 and 2 are now rejected; regenerate all checkpoints using the command above. The new
`original_elm_return` scenario continues every post-rival starter through naming,
Egg handoff and lab re-entry, without injected story flags.

Version 3 replaces the selective story snapshot with the complete original
normal-record owner and exports full field/object state into checkpoint data.
Versions 1 and 2 are rejected. Regenerate using `heartgold_checkpoints`.
These development snapshots remain distinct from the original-manager cartridge
Save/Continue controls; see [save acceptance](save-acceptance.md).

## Gameplay-produced Violet arrival saves

`cmake --build build --target test_violet && ./build/test_violet` continues each
post-tutorial starter through Route 30/31, Mom’s savings call and the original
gatehouse Vs. Recorder gift/departure. It saves and reopens Route 30, the moved
gatehouse population and Violet, then publishes ordinary native cartridge saves:

- `build/checkpoints/152-violet-arrival.sav`
- `build/checkpoints/155-violet-arrival.sav`
- `build/checkpoints/158-violet-arrival.sav`

Open these with the native viewer’s **Continue…** button. They retain the actual
opening party and original flags; no curated team or progression flags are
injected. Totodile’s scenario accepts Mom’s savings offer; the others refuse.
These are Violet arrival saves, not first-badge checkpoints. The `--probe` option
continues to Sprout Tower 2F/Sage Nico, where standard trainer opcode 212 currently
rejects. Route planning uses the saved story’s actor population and the same
input/event/menu driver as opening regression scenarios.
