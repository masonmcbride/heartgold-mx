# New Bark walking

Run `./build/heartgold_field_viewer`, select New Bark (60), click the scene and hold WASD. W/S move north/south and A/D west/east in world coordinates, independently of camera orbit. Release stops input. The camera follows each committed step. Drag/arrows orbit, scroll or +/− zoom, shift-drag pans, and R recenters on the player. Moving keyboard focus away from the scene or deactivating the window clears held input. Switching maps creates a fresh inspection session; other maps retain camera inspection controls.

The native session owns original `LocalMapObject`, `MapObjectManager`, `PlayerSaveData` and `PlayerAvatar` state. A deterministic spawn search near tile (688,398) admits a non-wall tile with an ordinary walking exit. This is a native session spawn, not original new-game/script execution. A nominal 60 Hz timer drives original field-task/application dispatch. Its native scene callback attempts a discrete step every eight ticks while input is held. This cadence is a host presentation policy, not original movement-controller timing.

Each step uses original directional input resolution, original player collision-mask execution, original grid-step bookkeeping and original Q12 tile-center conversion. Height, directional terrain, occupancy and cycling restrictions execute through the boundaries documented in [playable integration](playable-integration.md). Nonzero masks prevent ordinary walking, including special movement requirements. Missing resources/unsupported execution do not commit an object update. The scope remains static New Bark with no dynamic platforms or active gym gimmick.

The hero uses original mmodel resource 69's textures and its type-7 mesh, with directional stepping presentation described below. It shares the terrain/prop raster and depth buffer, so buildings and trees can occlude it. This does not execute original sprite animation controllers, lighting or object-render tasks. The default camera starts near the player rather than fitting the entire town.

The application test verifies that input progresses through simulation ticks, changes both original coordinates and rendered pixels, stops on key release, and eventually stops at a collision boundary under sustained input. Rendering does not itself advance simulation. The AppKit smoke test sends WASD key-down and key-up events and verifies movement and stopping alongside map/character browser behavior. A rendered New Bark frame was visually inspected to confirm visible spawning on the path. The full motion corpus separately covers 3,968 neighbor edges, height thresholds, water/cycling checks and synthetic object occupancy. Actual map-event NPC population, original animation-controller execution, interactions, jumping/surfing, doors/warps, map transitions, saves and full original game startup remain pending.

## Directional stepping presentation

The player now selects the original hero type-7 mesh (member 272), following `SPRITE_HERO` in `overlay_01_sprite_data.s`, rather than generic member 266. Its 16-unit width and 34-unit height replace the previous native 16-by-24 normalization. The mesh's 16-pixel U span binds the centered strip of each 32-by-32 hero frame with a native U offset of 8. This fixes the compressed appearance without scaling the map or collision grid.

The native presentation caches all 32 original `hero.N` textures. Inspected standing frames are north/south/west/east 1/5/9/13; paired step poses are 2 & 4/6 & 8/10 & 12/14 & 16. Native scheduling alternates stepping feet and standing poses during the existing eight-tick cadence. Blocked attempts turn the actor without playing a walking step. A committed logical position remains governed by original collision/grid code; its visual position interpolates over eight simulation ticks. Releasing input finishes that presentation step, then stands still. Camera following uses the interpolated position, and a presentation revision triggers redraws for pose changes as well as motion. Rendering itself never advances animation.

This executes original texture/mesh data, not the original animation controller or its timing tables. The character gallery remains a static inspection view. Tests check intermediate displacement, stride-to-idle transition, settling on key release and no animation advance on redraw/idle ticks. The corrected mesh and UV alignment were visually inspected in the native renderer.
