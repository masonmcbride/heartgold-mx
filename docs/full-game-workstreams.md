# Full-game build and execution workstreams

The whole-game source inventory is now generated by `cmake --build build --target audit_native`. Read [the generated solution matrix](../build/audit/WORKSTREAMS.md), [every indexed function](../build/audit/remaining-functions.csv), and [per-source errors and solution assignments](../build/audit/workstreams.json). The original manifest selects 706 source units: 415 C and 291 assembly, including support libraries and separately identified DSProt sources. The function index contains 29,745 lexical C definitions and assembly markers, not 29,745 outstanding functions. It is not preprocessor-aware execution coverage.

The finite set below organizes the work. A shared boundary can remove the same obstacle from many callers. This does not make each family a single patch: fixing a missing include exposes previously hidden type errors, imports and runtime dependencies. No static inventory can establish that unexecuted branches work. The generated report records visible secondary families as well as each unit's primary assignment. Zero units assigned to a family means it is hidden behind earlier compiler barriers, not complete.

| Family | Shared solution | Done when |
| --- | --- | --- |
| Generated resources | Generate indices from original message/archive manifests, with validated IDs and tracked input dependencies | Required includes and symbols resolve, and indices match real archive members |
| ABI and declarations | Share audited scalar/record interfaces; explicitly marshal guest pointers, native pointers and callbacks | Independent layout vectors and ownership/callback tests pass across each boundary |
| Graphics and UI | Bind original GX/NNS state, resource lifetimes and scene control to existing DS readers and native rendering | Original scenes produce verified output and release resources correctly |
| Audio | Supply shared archive, voice/sequence and sound-handle services | Sound output and original completion/wait semantics work |
| Host platform | Connect clocks, input, filesystem and original task queues to host services | Deterministic lifecycle, time/input and bounded IO scenarios pass |
| Persistence | Own original save blocks and implement serialization/checksum/atomic storage at the save boundary | New game, save, reload, corruption rejection and cancellation preserve state |
| Communications/peripherals | Provide explicit backend capabilities for wireless, online and accessories | Supported operations work; unavailable services fail visibly |
| ARM/Thumb execution | Reuse the guest engine/import bridge, evaluating a broader CPU backend against measured gaps | Original instructions and all required imports execute correctly; native ARM64 assembly is not a substitute |
| Original subsystem integration | Compile original call closures and connect their shared owners through field, scripts, menus and battles | Continuous gameplay scenarios pass through original entry points |
| Diagnostic review | Resolve ambiguous evidence before inventing interfaces | Current barriers have verified assignments; the next survey reveals deeper barriers |

The report assigns whole-source compilation obstacles. A failed file can already supply compiled and executed slices; a successfully compiled file can still depend on unsafe pointer casts or unsupported host services. Undefined-symbol reporting covers successful objects only. Provider matches include all twelve built static archives, record their hashes, and do not establish a complete link or service implementation. C function indexing and provider discovery are lexical hints, not a complete compiler call graph. The survey excludes SDK implementations, host asset tools and ARM7 firmware; the DSProt source group is not substituted for the archive used by the original build.

## Shared fixes applied

- Message index preparation now covers all 828 original JSON banks and both upstream include spellings. IDs are validated, original ordinal values are retained, source hashes are recorded, and no message text is emitted into headers. Generated outputs remain ignored. Every message JSON is tracked for regeneration, including added/removed banks. This removes the entire observed missing-message-header class, rather than extending a caller allowlist.
- `MI_CpuClear8` now has its missing public boundary declaration; its implementation already delegates to `memset`.
- Message load constants now match the original enum (`DIRECT=0`, `LAZY=1`). Direct loading remains explicitly unsupported; declaring its original value does not implement it.
- Pokemon closure regeneration now tracks every source/resource/declaration recorded in its provenance, so adding a dependency no longer depends solely on maintaining a manual list of roots.
- The compiler survey resolves providers against all twelve built static archives (including field tasks, overlays, props, platform and view/application services). It previously consulted only logic and field, which could misreport existing providers as missing.

## Implementation order

Use generated diagnostics to remove verified shared ABI/resource obstacles first, rerunning after each class of changes. In parallel with compilation, continue the connected Elm-lab scenario: original starter choice task, post-choice script services, follower owner/controller and map transition. This forces the common services to satisfy a real gameplay path. The original received-starter task now executes in standalone tests with actual choice, trainer/encounter metadata, party insertion, Pokedex and score updates; the connected application now completes the default-name choice/follower route for all three starters, including the original standard item gift and lab re-entry. Original naming, boot, saving and battles remain unconnected.

Then connect original menus, battle orchestration, saving and broader map lifecycle through those same services. Avoid an independent native rewrite of each caller, placeholder SDK structs, silent success handlers, or using object counts as a playable-game percentage. Original ARM-only subsystems require a deliberate guest execution strategy; adding declarations cannot solve their instructions or ABI.

Detailed compiler logs, original-source excerpts, objects, hashes and generated indices stay under ignored build directories. No upstream files, original assets, ROM or proprietary SDK components are changed or added to version control.

## Verification for this checkpoint

The rerun emits 36 of 415 C objects, compared with 32 before these shared fixes. The other 379 C units still fail, and all 291 ARM assembly units remain incompatible with native ARM64 assembly. The latter result does not negate the separately assembled, linked and executed guest slices. All 30 current CTests pass in normal and ASan/UBSan builds. Upstream source hashes match and its Git checkout remains unmodified. These results establish a verified batch improvement and reproducible remaining-work inventory, not a full-game build.
