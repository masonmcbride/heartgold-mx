# Original background events and sign scripts

In New Bark, face the town sign or Elm's lab sign and press **Enter** or **Space**. The native dialogue panel displays the original message using the existing original font renderer. The same button closes it. Walking pauses while the panel is open; an in-progress visual step settles before a queued interaction runs. This slice does not execute name-dependent house signs, hidden items, NPC conversations or story/warp scripts.

From the inspection spawn, two west steps and two south steps put the player at (686,400). Attempting another west step faces the town sign at (685,400), where Enter opens its message. The lab sign is at (682,393). These are original background event coordinates, not native proximity triggers.

## Original data and code reused

`scripts/prepare_interaction.py` compiles and runs the unchanged upstream `tools/jsonproc/jsonproc.cpp` with the original `zone_event.json.txt` template. Clang resolves original constants and emits the data. The tool compiles inside the ignored build directory and is reused when its inputs have not changed. The original source tree is never modified. The shared local NARC writer packages the resulting members in original manifest order; the existing bounded NARC reader and process-lifetime cache load them.

Of 491 original event JSON members, 464 assemble without relocations. Twenty-seven reference unresolved original constants (principally `obj_EVERYWHERE_*`). Their member slots remain explicitly empty/unsupported; relocation placeholders are never accepted as original event values. `interaction_provenance.json` records unsupported member IDs and source hashes. The runtime validates exact record extents for backgrounds (20 bytes), objects (32), warps (12) and coordinate events (16), and rejects truncated/oversized/trailing data before guest execution. Decoded object/warp/coordinate arrays are available as borrowed bounded views, but their presence does not populate original NPCs or activate transitions.

The complete unchanged `asm/unk_0203DB6C.s` is assembled into the existing field guest image. Actual interaction executes original `GetInteractedBackgroundEventScript`, `_GetCoordsOfFacingTile` and `BgEventDirectionIsCompatibleWithPlayerFacing`. The field's avatar handle and validated background bytes are marshaled into bounded guest RAM. Original native avatar accessors supply coordinates and facing. Hidden-item records are excluded from this admitted visible-sign path because collected flags/save state are not implemented. The remaining routines in this assembly unit are assembled coverage, not demonstrated execution.

The complete original `scr_seq_0842_T20.s` bank is assembled using original script/movement macros and constants. It contains 5,964 bytes, including entry offsets, other scripts and movement data. All bytes remain build-local; generating the bank does not establish execution support for every entry. Original map-header getters verify the expected script/message bank relationship and supply message selection. Original message JSON is exposed through the existing UTF-8 resource boundary, not the serialized DS `String` representation.

The complete unchanged `src/script.c` compiles and links natively. Its original `ScriptContext` declaration and API are extracted into a private compatibility include, preserving native pointer ownership and avoiding unrelated SDK header dependencies. The sign path executes `InitScriptContext`, `SetupBytecodeScript`, `RunScriptCommand`, `ScriptReadHalfword`, `SetupNativeScript` and `StopScript`; `ScriptReadByte` is the original macro. Other original stack/jump/call/read APIs compile but are not established by these sign tests.

## Explicit native boundaries

The script dispatcher executes a native provider table for the admitted sign-presentation commands. These are **not** the original `ScrCmd_TrainerTips`, `ScrCmd_DirectionSignpost`, signpost animation implementations, or general `CallStd` lifecycle. They consume the original operands, select the message and use the original dispatcher's bytecode/native-yield/end states. The admitted `std_signpost` provider models immediate native presentation readiness. The original standard-script bank is not executed; the viewer separately owns modal display and button acknowledgment after the small extraction context has ended.

Before original pointer-based dispatch, the adapter validates a finite linear program of at most 32 commands, with known operand sizes, exactly one message and an End command. Unknown opcodes, non-signpost standard calls and placeholder-dependent text fail without changing caller output. Only original entry IDs 14 (lab sign) and 15 (town sign) currently pass. This does not provide general story execution, variable/flag mutation, formatting/profile names, text-speed/typewriter behavior, native original script tasks, or original signpost wipe animation. Unknown commands are never dispatched as successful no-ops. The accepted visual-only commands use native immediate presentation semantics.

`HGFieldApp` owns the interaction request, modal state and font lifetime. The panel reuses `hg_font_draw`, which executes original font-data/glyph routines. Scene rendering remains independent of simulation; interaction and modal changes increment the existing presentation revision. AppKit handles Enter/Space edges and suppresses key-repeat toggling. No additional renderer, font engine, CPU instruction implementation, external dependency or proprietary SDK component was introduced.

## Verification

`original_background_interaction` validates all 464 available event members and every truncation of each member, counts the 27 unsupported banks, tests original selector behavior from all four sides and all seven event-direction values, and rejects nonadjacent matches. It tests every New Bark script ID, exact original lab/town text, unsupported script/output preservation and short-buffer rejection.

The same test walks the real application from its spawn to the town sign through original collision-checked steps, opens the dialogue, verifies frozen coordinates while movement input is supplied, closes it and verifies a framebuffer change. The AppKit smoke test sends movement and Enter events through the actual canvas, verifies open/close behavior alongside existing browser checks, and saves an ignored `build/evidence/new-bark-dialogue.png` snapshot. That snapshot was visually inspected for player placement and original-font dialogue rendering. Normal and sanitizer builds exercise the new path with the existing movement corpus.

The next useful extension is persistent original script ownership with typed variable/flag/profile services, followed by event-object population and a real interaction/transition under that owner. Event decoding and script dispatch now have executable boundaries to build on; a compiled story bank alone is not a playable story.
